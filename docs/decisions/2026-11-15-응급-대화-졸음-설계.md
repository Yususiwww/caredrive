# 2026-11-15 심장 이상 · 무맥박 · 스트레스 대화 · 졸음 설계

담당자 요청(11/15)을 로직으로 옮긴 설계다. 숫자는 모두 **설계 예시**이고 의료 자문이 필요하다. 케어드라이브는 진단하지 않는다.

## 0. 확인한 사실 (Pleos SDK 2.3.2를 직접 열어 확인)

| 하고 싶은 것 | 가능 여부 | 설계 |
|---|---|---|
| 비상등 켜기 | **불가.** `TurnSignal`은 읽기만 된다(`getCurrentTurnSignalState`, `registerTurnSignalState`). `Light`에도 비상등 setter가 없다 | 차가 "비상등을 켜 주세요"라고 말하고, 켜졌는지 `TurnSignal`로 **감지**해서 화면에 체크 표시 |
| 실내 경고 연출 | 가능. `Light.setAmbientLightBrightnessColor`, `setCabinLightSwitch` | 무맥박·위급 단계에서 앰비언트를 붉게, 실내등 켜기(정차 후) |
| 졸음 차량 신호 | 가능. `SteeringWheel.registerSteeringWheelAngle`, `Brake.registerBrakePedalStatus`, `Gear` | 핸들 반전 빈도(SRR)와 무조향 시간 |
| 창문 | `Window` API 있음 | 졸음 1단계에서 "창문을 조금 열까요?" 제안만(자동으로 열지 않음) |
| 미디어 | Pleos SDK에 없음 | 폰이 플레이리스트를 재생하고 차는 블루투스로 듣는다(프로토타입: 폰 시뮬레이터가 "재생 중" 표시) |
| 전화 | Pleos SDK에 없음 | 폰이 건다. 차는 `call` 메시지만 보낸다(아래 4장) |
| 음성 인식 | Pleos SDK에 TTS만 있음 | 질문은 음성으로 하고 답은 큰 버튼 2개로 받는다. 음성 답(STT)은 다음 단계 |

## 1. 데이터 흐름: 워치 → 폰(기록) → 차(감지·확인)

```
워치(삼성 헬스 센서)  ──심박·박동간격·착용 상태──▶  폰 앱  ──요약·이벤트──▶  차 앱
                                                   │ 이벤트 기록(시각·종류·값)      │ 판단·질문·차량 제어
                                                   ◀──────── call / play 요청 ──────┘
```

- **폰은 모든 이상 이벤트를 기록**한다. 기록 대상은 부정맥 알림, 무맥박, 착용 해제, 심박 범위 이탈, 졸음 점수 상승이다. 기록은 시각, 종류, 값, 차가 보낸 응답 결과로 남긴다. 이 기록을 보호자 알림과 병원 방문 때 보여 준다.
- **차는 받은 이벤트와 차량 신호를 합쳐 단계를 정하고 운전자에게 직접 묻는다.**

## 2. 흐름 A: 심장 이상 → 확인 질문 → 비상등·연락

트리거: 새 부정맥 알림, 또는 심박 < 40 / > 140, 또는 안정 심박 +30 이상 5분 지속(기존 L2 조건).

1. 차가 묻는다. 화면과 음성 문구가 같다.
   > "심장 박동이 평소와 달라요. 괜찮으세요?"
   - 버튼: **[도움이 필요해요]** **[괜찮아요]**
2. **[괜찮아요]** 를 누르면 기존 L2 흐름으로 간다. 휴게소 안내를 제안하고, 같은 이유로는 15분 동안 다시 묻지 않는다.
3. **[도움이 필요해요]** 를 누르거나 **30초 동안 답이 없으면** 다음을 한다.
   - 차가 말한다: "비상등을 켜고 갓길이나 안전한 곳에 세워 주세요. 멈추면 바로 연락할게요."
   - 앰비언트를 붉게 바꾸고, 가장 가까운 휴게소·졸음쉼터를 경유지로 넣는다.
   - 비상등이 켜지면(`TurnSignal` = 비상등) 화면에 "비상등 켜짐 ✓"을 표시한다.
   - 기어가 P가 되면 **연락 단계**로 간다(4장).
4. 폰 기록: `cardiac_check` 이벤트에 운전자의 답(괜찮아요 / 도움 / 무응답)을 남긴다.

## 3. 흐름 B: 무맥박 → 즉시 질문 → 3분 무응답이면 자동 연락

워치가 **착용 상태인데 맥박이 잡히지 않음**을 보낸다(`pulse: "absent"`). **착용 해제**(`pulse: "offwrist"`)는 다르게 다룬다. 이때는 "워치를 다시 차 주세요"라고만 말하고 단계를 올리지 않는다. 오탐을 막기 위해서다.

| 시간 | 차 | 폰 |
|---|---|---|
| 0초 | 경고음 3회 + "괜찮으세요? 대답해 주세요." 앰비언트 붉게 | `no_pulse` 기록 |
| 0–60초 | 20초마다 다시 묻는다. 화면: **[괜찮아요]** 큰 버튼, 남은 시간 원형 게이지 | |
| 60초 | "1분 동안 대답이 없어요. 2분 뒤 119와 보호자에게 연락해요. 괜찮으면 '괜찮아요'를 눌러 주세요." | 보호자에게 **미리 알림 문자**(위치 포함) |
| 180초 | "119와 보호자에게 연락하고 있어요." 실내등 켜기(정차 시) | `call` 처리: 보호자 전화, 119 연결(4장) |

- 어느 시점이든 **[괜찮아요]** 를 누르면 취소된다. 취소도 기록하고, 맥박이 다시 잡히면 "맥박이 다시 잡혀요"라고 알린다.
- 3분은 담당자가 정한 값이다. 삼성 워치의 넘어짐 감지는 약 1분 무응답 뒤 SOS를 보낸다(조사 결과로 보완). 그래서 **60초에 보호자 미리 알림, 180초에 전화**의 2단으로 둔다.
- 주행 중이면 차를 세울 수 없다(케어드라이브는 차를 제어하지 않는다). 소리와 빛으로 깨우고, 비상등을 켜 달라고 말하고, 연락을 앞당길 수 있게 한다.

## 4. 연락 단계 (흐름 A·B 공통)

- 차 → 폰 `call` 메시지: `{ type: "call", to: ["contacts", "119"], reason, location }`
- 폰이 하는 일 (실제 앱 기준, 조사 결과로 확정)
  - **지정 연락처**: 바로 전화(`CALL_PHONE`)와 위치 문자. 보호자 1~3명.
  - **119**: 일반 앱은 긴급번호로 바로 걸 수 없어서 **다이얼러에 119를 채워 띄운다.** 무응답 상황을 위해 **119 문자신고**도 함께 보낸다. 문자에는 위치, 차종, "운전자 무응답 3분", 최근 심박 기록을 담는다.
- 차 화면: "연락 중: 보호자(엄마) · 119" + **[취소]** 버튼. 10초 카운트다운(eCall 패턴)은 흐름 A(운전자가 직접 도움 요청)에만 쓴다. 흐름 B에서는 이미 3분을 기다렸으므로 바로 연락한다.
- 시연(폰 시뮬레이터): 실제 전화를 걸지 않는다. "보호자에게 전화 거는 중 · 119 문자 보냄"을 화면에 보여 준다.

## 5. 흐름 C: 긴장·스트레스 → AI가 묻고 → 플레이리스트

트리거: 기존 L1(심박 지속 상승) 또는 HRV 스트레스가 기준보다 높은 상태가 5분 이어질 때. 주행 중이고 다른 경고가 없을 때만 묻는다.

1. 차가 묻는다: "많이 긴장하신 것 같아요. 힘든 일이 있었나요?"
   - 버튼: **[좀 그래요]** **[괜찮아요]**
2. **[좀 그래요]** 를 누르면 차가 말한다: "좋아하시는 노래 틀어 드릴게요. 천천히 숨 쉬어 보세요."
   - 차 → 폰 `play` 메시지: `{ type: "play", playlist: "calm" }`
   - 폰이 미리 정한 플레이리스트를 재생한다. 플레이리스트가 없으면 차에서 듣던 미디어를 이어서 튼다.
   - 실내를 시원하게 하는 기존 동작도 유지한다.
   - 화면: 지금 재생 중인 플레이리스트 이름 한 줄.
3. **[괜찮아요]** 를 누르면 기존 호흡 안내만 하고, 같은 이유로는 15분 동안 다시 묻지 않는다.
4. 대답은 기록만 하고 분석하지 않는다. 감정 내용은 차 밖으로 보내지 않는다.

## 6. 흐름 D: 졸음

워치만으로 졸음을 정확히 알기는 어렵다. 그래서 **차 신호와 합친 점수**를 쓴다. 근거는 조사 결과로 보완한다.

`졸음 점수 0–100` = 다음 항목의 합(상한 100):

| 항목 | 출처 | 점수 (설계 예시) |
|---|---|---|
| 지난밤 수면 부족 | 삼성 헬스 수면(또는 폰에 직접 입력) | 5시간 미만 +25, 6시간 30분 미만 +10 |
| 연속 운전 | 차 | 오늘 휴식 간격의 80% 이상 +15 |
| 시간대 | 차 시계 | 02–06시 +20, 14–16시 +10 |
| 심박 저하 | 워치 | 안정 심박보다 8 bpm 이상 낮은 상태가 3분 이상 +20 |
| 심박변이도 상승 | 워치(RMSSD) | 평소보다 30% 이상 높은 상태가 3분 이상 +10 |
| 핸들 | 차 `SteeringWheel` | 반전 빈도가 평소보다 크게 떨어지거나, 10초 넘게 조향이 없다가 큰 수정 조향이 나오면 +20 |

- **40 이상 (L1)**: "졸음이 올 수 있어요. 실내를 시원하게 할게요. 창문을 조금 열까요?" 공조를 시원하게 맞춘다.
- **60 이상 (L2)**: "가까운 졸음쉼터에서 쉬어 가요." 가장 가까운 졸음쉼터를 경유지로 넣고, 경고음은 2회로 한다.
- 수면만 아는 경우(워치 실시간 신호 없음)에는 지금처럼 **휴식 간격을 앞당기는 것**까지만 한다.

## 7. 화면 (디자인 D, 콕핏 계기판)

- **주행 정상**: 심박 게이지와 다음 휴식 게이지. 졸음 점수는 작은 막대로만 보여 주고, 숫자는 보여 주지 않는다.
- **질문 화면 (흐름 A·C·D)**: 게이지가 왼쪽 레일로 줄어들고, 가운데에 질문 한 줄과 큰 버튼 2개가 온다. 확인 버튼을 먼저 둔다.
- **무맥박 화면 (흐름 B)**: 가운데에 남은 시간 원형 게이지(3:00)와 "괜찮으세요?", 그 아래 **[괜찮아요]** 버튼 하나가 아주 크게 온다. 비상등 상태를 체크 표시로 보여 준다.
- **연락 중 화면**: 연락한 곳 목록(보호자 ✓, 119 문자 ✓)과 **[취소]**.
- **재생 중**: 하단에 "♪ 편안한 플레이리스트 재생 중" 한 줄.

## 8. 폰 ↔ 차 메시지 추가 (docs/protocol.md 반영)

| 방향 | type | 필드 |
|---|---|---|
| 폰 → 차 | `pulse` | `state`: `present` / `absent` / `offwrist` |
| 폰 → 차 | `live` | 기존 필드 + `wrist`(bool, 선택) |
| 차 → 폰 | `ask` | `ask`: `CARDIAC_CHECK` / `NO_PULSE` / `STRESS_TALK` / `DROWSY`, `answer`(나중에 보냄) |
| 차 → 폰 | `call` | `to`: `["contacts","119"]`, `reason`, `stage`(`pre_alert` / `call`) |
| 차 → 폰 | `play` | `playlist`: `calm` |
| 폰(시연) → 차 | `drowsy` | `steeringIdleSec`, `hrDrop`(시연용 신호 주입; 실차에서는 차 신호 사용) |

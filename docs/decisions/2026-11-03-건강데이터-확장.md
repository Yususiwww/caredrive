# 2026-11-03 심장 → 운전자 컨디션 전체로 범위 확장

## 결정
심장(부정맥·심박)에만 한정하지 않고, 워치가 아는 건강 정보를 모아 **운전 컨디션**을 본다. 판정은 폰에서 하고 차에는 단계와 이유만 보낸다(기존 원칙 유지).

## 읽을 수 있는 데이터 (Samsung Health Data SDK, 폰에서 읽기)
| 데이터 | SDK 타입 | 운전에 쓰는 방식 |
|---|---|---|
| 수면 (시간·단계) | `SleepType` | 어젯밤 수면 부족 → 졸음 위험, 휴식 간격 단축 |
| 수면 무호흡 감지 | `SleepApneaType` | 감지 이력 → 상시 졸음 주의 |
| 에너지 점수 | `EnergyScoreType` | 오늘 컨디션 낮음 → 출발 전 안내 |
| 혈중 산소 | `BloodOxygenType` | 수면 중 낮은 값 → 졸음 위험 보조 지표 |
| 심박 | `HeartRateType` | 상시 측정 시 실시간에 가까운 심박 |
| 부정맥 알림 | `IrregularHeartRhythmNotificationType` | 기존 설계 그대로 |
| 피부 온도 | `SkinTemperatureType` | 참고 지표 (단독 판단 안 함) |
| 혈압 | `BloodPressureType` | 고혈압 기록 → 참고 지표 |
| 혈당 | `BloodGlucoseType` | 연속혈당측정기 연동 사용자: 저혈당 → 즉시 휴식 |
| 활동·운동 | `ExerciseType`, `StepsType` | 운동 직후 심박 상승 오탐 줄이기 |

## 스트레스
- Data SDK 타입 목록에 **스트레스와 심박변이도(HRV)는 없다** (2026-11 API 레퍼런스 기준).
- 워치 앱(Health Sensor SDK)의 박동 간격(IBI)으로 HRV를 계산해 **긴장도**를 자체 추정할 수 있다. 웰니스 안내 수준으로만 쓴다.
- 워치 앱은 실기 필요 → 7단계에서 결정.

## 운전 중 상황별 대응 (차량 쪽)
- 졸음 위험: 공조 시원하게, 졸음쉼터 안내, 휴식 간격 단축
- 긴장도·심박 상승: 공조 시원하게, 차분한 음성 안내
- 저혈당: 즉시 가까운 휴게소 안내 (경고 단계)
- 부정맥 알림: 기존 L2 → 정차 후 L3

## 미확인
- 각 타입의 읽기 권한 이름과 동기화 지연 (실기 6단계에서 확인)
- 에너지 점수 산정 방식 (삼성 비공개)

## 2026-11-07 추가 반영
워치 기능 전체 조사(갤럭시 워치9 / One UI 9 Watch 기준) 후 앱이 실제로 받을 수 있는 것만 판정에 넣었다.

| 입력 | 출처 | 판정 (예시 기준, 의료 검토 필요) |
|---|---|---|
| 수면 중 최저 산소포화도 | Data SDK `BloodOxygenType` | 90% 미만 주의(LOW), 93% 미만 보통(FAIR) |
| 피부온도 (개인 평균 대비) | Data SDK `SkinTemperatureType`, 평균은 폰이 계산 | +1.0℃ 이상 LOW, +0.5℃ 이상 FAIR (감기·피로 신호) |
| 수축기 혈압 (최근 1일) | Data SDK `BloodPressureType` | 180 이상 LOW, 160 이상 FAIR |
| 기분 | 출발 전 차 화면에서 한 번 선택 (정차 중에만) | 피곤해요·스트레스 → FAIR. 스트레스를 고르면 주행 중 스트레스 기준을 70 → 60으로 낮춤 |
| 실시간 스트레스 | 워치 앱 박동 간격(IBI) → RMSSD → 평소 값 대비 0–100 (`Hrv.kt`) | 기준 이상 5분 지속 → 주의(STRESS_HIGH): 공조 + 호흡 안내(4초 들이쉬고 6초 내쉬기), 15분 지속 → 경고 |

- 삼성 헬스의 스트레스 점수, 기분 기록, 바이탈 이상 알림, 심장 건강 점수, 혈관 부담은 외부 앱이 읽을 수 없어 쓰지 않는다.
- 우울증은 워치에 감지 기능이 없고 운전 판정에 쓰기에도 근거가 약해 다루지 않는다.
- 심박 상승(HR_SUSTAINED)이 스트레스보다 우선한다. 심박은 정상인데 HRV만 낮은 경우를 스트레스로 본다.

# 2026-11-03 프로젝트 구조와 개발 순서

## 결정
- 저장소 하나에 `car-app/`(Pleos 차량 앱), `relay/`(중계 서버), `phone-sim/`(폰 시뮬레이터)를 둔다. 실제 폰 앱은 6단계에서 `phone-app/`으로 추가한다.
- 1차 마감(11.15)까지는 맥 한 대(Pleos 에뮬레이터 + 로컬 중계 + 시뮬레이터)로 전 과정을 시연한다. 영상에는 "시뮬레이션 데이터"라고 표시한다.
- 위험 단계 판정은 폰에서 한다. 차에는 단계와 심박 숫자만 보낸다(데이터 최소화).
- 차량 앱은 진단하지 않고, 차를 직접 세우지 않는다. 제안만 하고 결정은 운전자가 한다.
- 빌드 설정은 마이테일러 Android 프로젝트(AGP 9.4.1, Kotlin 2.4.21, Compose BOM 2026.09.00)를 따른다. compileSdk 37(OkHttp 5.5.1 요구), targetSdk 34(Pleos 에뮬레이터 2.1.0), minSdk 28(Pleos 요구).

## 이유
- 부정맥 알림(IHRN)은 정지 상태에서 주기적으로 측정되고 약 1시간 누적 후 알림이 오므로 실시간 신호가 아니다. 사전 위험 신호(주의 모드)와 실시간 심박 두 갈래로 나눈다.
- 워치 앱(Sensor SDK)은 에뮬레이터를 지원하지 않는다. 심박 상시 측정 데이터를 Data SDK로 읽을 때 지연이 1~2분 안이면 워치 앱은 만들지 않는다(6단계에서 측정 후 결정).

## 미해결
- 실차에서 폰 ↔ 차 통신 방식(일반 인터넷/BLE 허용 여부) — 운영사무국 질의
- Pleos 권한 사전 승인 절차
- 기어·속도 값 읽기(AAOS CarPropertyManager) — 2단계에서 확인
